## Start with your agent

Open a checkout of a GitHub test repository and paste this prompt into your coding agent.

<Prompt description="Prepare a Tripwire workflow for this repository" actions={["copy"]}>

Help me prepare my first Tripwire workflow in this GitHub test repository.

1. Confirm the GitHub repository from the local Git remote. Use the stable Tripwire CLI. If it is missing, ask before installing it with `npm install -g @tripwire-sh/cli`.
2. Check the session with `tripwire status`. If sign-in is needed, run `tripwire login`, show me the browser link, and wait for me to sign in. If the repository is not connected, ask me to connect it in Tripwire.
3. Use the TypeScript SDK (`@tripwire-sh/sdk/workflows`). If `@tripwire-sh/sdk` is missing, ask before adding it to the project. Draft a workflow in `.tripwire/workflows/` that checks newly opened pull requests and sends them to Human review if they change more than one file. Preserve existing workflow files.
4. Validate the workflow locally with `tripwire workflows validate <slug>` and show me the result and proposed file. Ask before pushing, enabling a workflow, or opening a pull request.

</Prompt>

<Callout type="info" title="Browser sign-in">
  Complete sign-in in your browser when the **CLI** prints the link.
</Callout>

Review the proposed file and validation result. When you’re ready, ask the agent to push it for review. Approve the push, open **Workflows**, and select **Turn on workflow** before testing it. For the test, skip to [Inspect the first run](#inspect-the-first-run).

## Set up in the dashboard

Use a GitHub test repository where you can install the **Tripwire GitHub App**. Ask a contributor outside your organization to open the test pull request.

<Steps>
<Step>

## Connect a repository

Sign in to [Tripwire](https://app.tripwire.sh). From your org home, select **Connect repos**, choose GitHub, and follow the prompts to grant the app access to your test repository.

Return to Tripwire and open the repository from **Connected repos**. If it’s missing, check which repositories you selected during installation.

  </a>
</Frame>

</Step>
<Step>

## Choose a check

Open **Rules**. If **Max files changed** isn’t installed, add it from **Library**. Under **Installed**, set its file limit to 1.

Open **Workflows** and confirm the workflow for that rule is on. If you’re using a custom workflow, confirm that it runs when a pull request opens and includes the rule.

</Step>
<Step>

## Inspect the first run

Have the test contributor open a pull request that changes two files. In Tripwire, open **Activity**, find the pull request by number, and open its run.

<Callout type="info" title="What you should see">
  The run shows the result of **Max files changed** and the action it triggered. If you used the agent prompt, the pull request goes to **Human review**.
</Callout>

<Frame caption="This example run blocked a pull request that touched 201 files.">
  <a className="quickstart-image quickstart-image-run" href="/screenshots/run-result.png">

</Frame>

If no run appears, check that the workflow is on and that its trigger matches the event you tested.

</Step>
</Steps>
